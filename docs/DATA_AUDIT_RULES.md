# قواعد ومحركات تدقيق جودة البيانات (DATA_AUDIT_RULES.md)
## DataAudit AI Pro — Data Quality, Anomaly & Forensic Rules Specification

---

## 1. الفلسفة العامة لقواعد التدقيق
تم تصميم محرك التدقيق ليعمل بأسلوب الفحص متعدد الطبقات (Multi-Layer Audit Engine)، حيث تُفحص البيانات عبر قواعد محددة لكل سجل وعمود، وتُصنف النتائج وفق مستويات خطورة:
- **معلومات (Info / Blue)**: ملاحظة تنظيمية (مثل توحيد تنسيق التواريخ أو المسافات).
- **تحذير (Warning / Amber)**: اشتباه في تكرار أو تشابه نصوص أو عدم انتظام في الأرقام.
- **خطأ حرج / مؤشر تلاعب (Critical / Red)**: تناقض محاسبي، مبالغ سالبة محظورة، تكرار رقم فاتورة مع مبالغ مختلفة، أو محارف يونيكود خفية خطرة.

## 2. تفصيل قواعد التدقيق المنفذة

### القاعدة 1: التكرار المتطابق (Exact Duplicate Detection)
- **المعايير**: تطابق تام بين سجلين أو أكثر عبر جميع الأعمدة أو عبر حقول المفتاح الأساسي (Primary Keys مثل: رقم الهوية، رقم الفاتورة).
- **السلوك**: تمييز الصفوف المتطابقة مع الإشارة إلى الصف الأصلي والصفوف المكررة.

### القاعدة 2: التكرار بعد التطبيع اللغوي العربي (Normalized Arabic Duplicates)
- **المعايير**: تطابق النصوص بعد إزالة الفروق الإملائية الشائعة:
  - إزالة الهمزات: "أحمد" = "احمد" = "إحمد".
  - الياء والألف المقصورة: "علي" = "على" = "منى" = "مني".
  - التاء المربوطة والهاء: "فاطمة" = "فاطمه"، "شركة" = "شركه".
  - إزالة التشكيل (الفتحة، الضمة، الكسرة، التنوين) والتطويل.
- **السلوك**: إشعار المستخدم بوجود تكرار إملائي محتمل مع خيار التوحيد بنقرة واحدة.

### القاعدة 3: تشابه الأسماء الضبابي (Fuzzy Name & Entity Matching)
- **المعايير**: حساب مسافة ليفنشتاين (Levenshtein Distance) وتشابه Jaro-Winkler للأسماء والكيانات بنسبة تشابه تفوق 85%.
- **السلوك**: التنبيه إلى احتمال كتابة اسم المورد أو العميل أو الموظف بطريقتين مختلفتين (مثال: "شركة الأمل للتجارة" و"شركة الامل للتجاره المحدودة").
- **ملاحظة أمان**: التطبيق لا يدمج الأشخاص تلقائياً، بل يقدم تقرير تشابه للمراجعة البشرية.

### القاعدة 4: كشف المحارف الخفية ومشاكل الترميز (Invisible Characters & Unicode Probe)
- **المعايير**: فحص السلاسل النصية بحثاً عن:
  - المسافة ذات العرض الصفري: `Zero-Width Space (\u200B)`.
  - علامة ترتيب البايتات: `BOM (\uFEFF)`.
  - المسافات غير القابلة للكسر: `Non-Breaking Space (\u00A0)`.
  - محارف التحكم غير المرئية (Control Characters: `\u0000` - `\u001F`).
  - المسافات المزدوجة المتتالية والمسافات البادئة واللاحقة.
- **السلوك**: تنبيه بأن النص يحتوي على محارف غير مرئية قد تعطل البحث أو تدل على نسخ وتلاعب غير مقصود، مع زر لإزالتها فوراً.

### القاعدة 5: كشف الحقول الإلزامية الناقصة (Missing Mandatory Values)
- **المعايير**: وجود خلايا فارغة في أعمدة حيوية (رقم القيد، التاريخ، المبلغ، اسم المستفيد).
- **السلوك**: تمييز الخلية باللون الأصفر وعرض تنبيه بنقص البيانات.

### القاعدة 6: فحص سلامة التواريخ (Date Validity & Sanity Checks)
- **المعايير**:
  - تواريخ بتنسيقات غير متسقة داخل نفس العمود (مثل خلط DD/MM/YYYY مع MM/DD/YYYY).
  - تواريخ في المستقبل البعيد أو الماضي السحيق غير المنطقي.
  - تاريخ انتهاء يسبق تاريخ البدء في نفس السجل.

### القاعدة 7: انتهاكات قواعد الأعمال المحاسبية (Business Integrity Violations)
- **المعايير**:
  - مبالغ كميات أو أسعار سالبة حيث يفترض أن تكون موجبة.
  - عدم تطابق مجموع بنود الفاتورة مع الإجمالي النهائي.
  - عدم توازن ميزان المراجعة (إجمالي المدين لا يساوي إجمالي الدائن).

### القاعدة 8: كشف القيم الشاذة إحصائياً (Statistical Outlier & Spikes)
- **المعايير**:
  - حساب الانحراف المعياري ومقياس **Z-Score** للقيم الرقمية؛ تمييز أي قيمة يتجاوز فيها `|Z| > 3`.
  - طريقة المدى الربيعي (**IQR: Interquartile Range**): تمييز القيم خارج `[Q1 - 1.5*IQR, Q3 + 1.5*IQR]`.
  - مؤشر المبالغ الدائرية المشبوهة (Suspicious Round Numbers): صفقات متكررة بمبالغ مثل 10,000.00 أو 50,000.00 تصدر في تواريخ متقاربة لتفادي حدود الصلاحيات.

## 3. هيكل مخرجات التدقيق (Audit Finding Schema)
لكل ملاحظة يتم إنشاؤها:
```typescript
interface AuditFinding {
  id: string;
  ruleId: string;
  ruleName: string;
  severity: 'info' | 'warning' | 'critical';
  sheetName: string;
  row: number;
  col: number;
  cellRef: string; // e.g. "C14"
  originalValue: any;
  suspectReason: string;
  similarityScore?: number;
  suggestedValue?: any;
  status: 'pending' | 'accepted' | 'rejected' | 'dismissed';
}
```
